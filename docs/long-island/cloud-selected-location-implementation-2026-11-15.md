## Implemented

React's actual static markers, regional point/line/polygon features and wind markers now retain a `selected-location-v1` snapshot through normalization, explicit Send to Chat, request serialization, Edge validation, request scope, controlled answer records and retained source/history metadata. Streamlit carries the same contract in popup/tooltip tokens for static markers, tidal gauges, regional vectors, wind observations and user-added layers, consumes it on the explicit chat action, and retains it in the user turn and assistant scope. Streaming and finalization previously discarded assistant metadata in Streamlit; they now preserve it.

The shared policy defines a 48 KiB location limit, 1,024 coordinate positions, 16 scalar attributes and 1,024 Unicode characters per text field (attribute names: 128). Supported EPSG:4326 geometry is Point, MultiPoint, LineString, MultiLineString, Polygon and MultiPolygon. Coordinates must be finite longitude/latitude pairs; lines and closed polygon rings have minimum sizes. Coordinates are not simplified, sliced or replaced with a centroid. Invalid or overcomplex source geometry becomes explicitly unknown during client construction; malformed geometry submitted directly to the server is rejected. Attributes are bounded source snapshots with source-URL attribution, never independent verification or instructions. Missing IDs, source URLs, feature types and times remain null with explicit unknowns. No identity is fabricated from an array index.

The server validates version, allowed fields, payload size, geometry, attributed attributes and timestamps. Selected NWS station IDs remain restricted to the configured catalog, and a conflicting legacy station selector is rejected. URLs are retained as provenance and are never fetched from this contract. Server-owned provider, timezone and application scope settings remain in place.

The selection is bound to the application's generated map question, ignoring outer whitespace. A request carrying that snapshot with a different question receives unresolved location scope and one focused clarification record; no location/weather/KB assertions are rendered from that mismatched request. Ordinary typed questions carry no active selected location. Historical selections remain inspectable, but are not reapplied to later typed requests.

Application jurisdiction and local jurisdiction are separate. No authoritative municipality/county lookup has been configured in this increment: local jurisdiction and facility footprint remain explicitly unresolved, even for a named station or a boundary-crossing vector. This is a deliberate remaining Batch 1 item, not a completed geographic assignment. A station point does not establish an airport footprint or emergency authority.
