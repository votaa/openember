## Source decision

Use the existing configured **NYS Civil Boundaries** service, extending administrative lookup to its Counties (2), Cities_Towns (6) and Villages (7) layers. Keep the Nassau-only `nassau_town_boundaries` prototype disabled. Its current configuration still gates reuse/attribution/ownership/update-cadence confirmation and it provides no Suffolk coverage. The selected lookup is a separate server-owned policy; it does not change map overlay visibility, regional filtering or the configured application jurisdiction.

Before integration, the proposed layers, statewide coverage and attribution were presented to the user in this implementation session. No new provider, paid service or geocoder was introduced. The NYS publisher and service are already used in the app; the city/town and village query layers are new uses of that dataset.

The [NYS Civil Boundaries program](https://gis.ny.gov/civil-boundaries) describes statewide counties, cities/towns and villages, with changes informed by authoritative sources. It expressly limits the GIS data to planning and general use, distinct from legal boundary records. The [configured service](https://services6.arcgis.com/EbVsqZ18sv1kVJ3k/arcgis/rest/services/NYS_Civil_Boundaries/FeatureServer) reports March 2026 publication, updates as needed and 1:24,000 positional accuracy. The configured publication date is the reviewed dataset edition, not a runtime guarantee of legal currency. Exact reviewed layer metadata is retained in [source-review](acceptance/boundary-local-2026-11-15/source-review/).

## Behavior and provenance

`shared/jurisdiction-lookup-policy.json` fixes publisher, source URLs, layers, fields, coverage and query limits. The Edge handler first validates the complete chat request, then queries those fixed endpoints on the server. Streamlit uses the corresponding Python lookup before resolving request scope. Client names, URLs, attributes and supplied `local_jurisdiction` fields cannot select endpoints or provide administrative matches. No name geocoding occurs, and a mismatched question makes no boundary request.

The lookup sends the **complete selected geometry**, in EPSG:4326, as a read-only ArcGIS POST spatial-intersection query. It supports points/multipoints, full line paths and polygon/multipolygon rings, including holes. Polygon winding is converted to ArcGIS shell/hole conventions without simplifying vertices or replacing any footprint with a centroid. All layers are queried statewide rather than restricted to the application's Nassau/Suffolk operating region. This prevents a crossing into another NY county from being silently filtered away. NYS coverage does not establish a jurisdiction outside New York.

Results describe **administrative intersections of supplied map geometry**. Multiple matches are retained. They do not establish that a whole feature lies within one jurisdiction, that a station point represents a facility footprint, or that any agency has ownership, dispatch, command or emergency authority. Cities/towns and villages remain separately labelled; a village result does not replace a town result. Point-on-boundary and crossing geometries can return multiple names, which are not reduced to one guessed jurisdiction.

Each administrative level retains its source/query URL, fetched time, record IDs, names, municipal type, county/town attributes where supplied, FIPS composite code, source `DATEMOD` when supplied and original source response. NYS county codes have 5 digits, city/town composites 10, and village composites 15. Live testing caught the village-specific format and a regression fixture now requires the real Farmingdale record to survive. Missing `DATEMOD` stays null; fetch time is not substituted for source modification time. Original responses remain inspectable and retained in **Application request scope · source metadata** in React and Streamlit history.

The three queries run concurrently, with a six-second request timeout, a 32 KiB response limit per layer, at most 32 matches per level and redirects rejected. An upstream error, retrieval failure, oversized or malformed response, duplicate/invalid record, or transfer-limit indication makes that level unavailable. Other valid levels survive with an incomplete-coverage message. Empty results, missing geometry and unavailable sources remain distinct. The bounded answer renderer receives application-owned administrative records; arbitrary provider prose remains disallowed.

## Validation

- Final phase-4 gate: **202 JavaScript checks and 161 Python test runs**, including repeated shared suites, config validation, build, compilation and whitespace checks. [Gate log](acceptance/boundary-local-2026-11-15/phase4-gate.log).
- Shared JS/Python checks require matching geometry query payloads for point, line, polygon and multipart fixtures, including polygon holes. They compare normalized source results and substantive answer records. Positive and failure cases cover the real village identifier, multiple jurisdictions, missing geometry, changed questions, client-spoofed jurisdiction fields, invalid requests before egress, failed/truncated/oversized responses and the actual Edge handler's streamed scope and answer.
- [Live public-source checks](acceptance/boundary-local-2026-11-15/live-source-results.json), with no model calls, returned Suffolk/Babylon for the supplied KFRG point and Nassau/North Hempstead for the supplied hospital point. A synthetic crossing road retained Nassau and Suffolk plus three town intersections. A crossing polygon retained both counties, five towns and Farmingdale village. A coastal point received source-supported intersections; an ambiguous name without geometry made no query. The successful JS live run measured 155–415 ms per geometry after the earlier cold/source-adapter check; these samples are not a latency service guarantee. Source fields, complete responses, geometries and exact fetch times are retained.
- The [local React browser check](acceptance/boundary-local-2026-11-15/browser-results.json) exercised actual KFRG and hospital marker → Send to Chat, visible administrative matches, complete request metadata, collapsed sources, retained history and no selection carryover into a subsequent typed question. It made six local boundary queries and two local recording-provider calls, with **zero cloud generations**. Captured public source replies were used for browser transport/rendering; this is not hosted acceptance. Screenshot under `output/playwright/selected-location-batch1.png` was visually inspected.
- Streamlit has the same contract/lookup/answer-record tests, live public-source checks and compilation coverage. A new full Streamlit browser walkthrough has not been performed.
